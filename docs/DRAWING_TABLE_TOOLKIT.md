# Таблицы на чертежах — каталог инструментов для BendCore CAD Pro

Дата проверки: **2026-11-02**. Статус: **анализ и проектная спецификация**. Этот документ не добавляет команды в интерфейс.

Сводка: **123 возможности в 16 группах**, 21 первичный источник по **9 CAD-системам и одному BIM/отчётному ориентиру**. Каталог объединяет проверенные функциональные образцы и требования BendCore, а не повторяет меню одного продукта. Машиночитаемая версия: [DRAWING_TABLE_TOOLKIT.json](DRAWING_TABLE_TOOLKIT.json).

Это продолжение [каталога текста](DRAWING_TEXT_TOOLKIT.md). Оно не является проверкой всех существующих CAD, версий и лицензий. Непроверенные продукты не получают ни отметку «поддерживается», ни отметку «нет функции». Наличие функции у одной CAD не подтверждает её у остальных.

База анализа кода: `e804ed2b679f13ef73a22e055e3d84b3d6d0d921` в main после слияния [PR #10](https://github.com/Do4ent/CADGUI/pull/10). Все ID `TBL-*` имеют `status: planned`, `runtimeIntegration: false`. Существующие `TXT-007`, `TXT-008` и `TXT-065` не переименовываются и не считаются реализацией нового набора.

## Главный вывод

Таблице нужен собственный редактор сетки и модель ячеек. Редактор обычного текста следует переиспользовать **внутри активной ячейки**, а не применять к таблице как к одной строке. Текущий `rows: TextParagraph[][][]` сохраняет текст ячеек, но не выражает их устойчивую идентичность, объединения, типы, формулы и связанные продолжения.

## Границы сущностей

| Сущность | Источник и смысл | Граница реализации |
| --- | --- | --- |
| Обычная текстовая таблица | Пользовательская прямоугольная сетка, текст, значения, стили | Базовый редактор; не требует точного CAD-ядра |
| Таблица свойств | Выбор объектов и отображаемых свойств | Нужны стабильные ID и правила обновления |
| BOM / спецификация | Структура сборки, количества, уровни, свойства и позиции | Отдельная вычисляемая проекция; ручная сетка не является BOM |
| Таблица ревизий | Записи изменений, автор, дата, статус | Нужна модель ревизий; не объявлять наличие release management |
| Отверстия и сгибы | Реальные CAD-элементы, начало координат, развертка, размеры | Без topology/feature backend автоматические таблицы недоступны |
| Ведомость раскроя | Каркас, профили, длины, количества | Нужен cut-list источник, а не эвристика по названиям деталей |
| Основная надпись | Схема полей листа/документа и шаблон штампа | Отдельная семантика, можно использовать общий renderer сетки |
| Excel/CSV | Внешняя книга/лист/диапазон либо снимок данных | Импорт не равен связи, связь не равна полному Excel-движку |
| Worksheet / BIM schedule | Запрос к объектам и отчёт | Vectorworks — ориентир; BIM-совместимость BendCore не заявляется |

Часть найденных адресов оказалась ошибочной, перенаправляла на главную или была недоступна; такие страницы не включены в подтверждённые источники.

## Состояние BendCore сейчас

| Область | Существующая основа | Что ещё требуется |
| --- | --- | --- |
| Схема | `src/drawing/types.ts`: `kind: table`, `rows[row][column]` содержит массив абзацев | ID ячеек/строк/колонок, прямоугольность, merges, типы, формулы, отдельные размеры |
| Создание | `operations.ts`, `CommandDialog.tsx`: TXT-007, размеры, TSV; TXT-008 — штамп с полями | Изменение структуры после создания, выделение диапазонов, редактор ячеек |
| Редактирование | Общие форматирующие команды обходят runs ячеек | `TextEditor` редактирует `entity.paragraphs`, а не `rows`; двойной клик не даёт полноценного табличного редактора |
| Отображение | `render/EntityGraphic.tsx`: сетка, rich text, поля, переносы | Равные высоты и ширины по числу ячеек строки; отступ 1 мм и линия 0,25 мм фиксированы. Нет вертикальной компоновки ячейки/drag-resize/merges |
| Стили | Есть общий текстовый стиль и формат runs | Нет каскада table/role/row/column/cell; маска текста не является заливкой ячейки |
| Поля и числа | Поля в runs, числовое выражение и вывод единиц | Нет A1-графа, межъячеечных формул или типизированной размерной величины; суффикс единицы не равен расчёту с единицами |
| Импорт | `DrawingWorkspace.tsx`: TSV либо разделитель `;`, снимок данных | Нет RFC 4180 quoting, quoted multiline, выбора кодировки/локали, XLSX или обновляемого datalink |
| Сохранение | Native JSON schema v2, независимые документы, общая история чертежа | Миграция расширенной сетки; undo после перезагрузки не сохраняется |
| Выделение | Выбор и перемещение объекта таблицы на листе | Hit testing ячеек, диапазоны, адреса и grid-навигация |
| Экспорт | SVG/PDF листа; DXF как независимые TEXT/MTEXT/LINE | Нет DXF TABLE round-trip, отдельного CSV/TSV/XLSX-экспорта или формул в PDF |
| Диагностика | Поля/Unicode/орфография обходят ячейки | Overflow конкретной ячейки сейчас не проверяется; нет пагинации таблицы и повторяемой шапки |
| Тесты | Создание/TSV/сохранение/отрисовка, разложение в DXF, защита от разрушительного merge | Нужны отдельные сценарии cell editor, structural edits, merges, формул, CSV, pagination и reopen |

`missing` в JSON означает отсутствие нужного workflow; `foundation` — только общий примитив или отрисовку; `partial` — ограниченный существующий путь. **Ни одна из этих отметок не означает, что команда TBL уже зарегистрирована или полностью реализована.**

## Предлагаемая модель и зависимости

Это проект, не уже существующая схема:

- `TableModel`: `id`, вид таблицы, `rowIds`, `columnIds`, `cells`, объединения, роли строк, именованные стили, источники и версии.
- `TableCell`: устойчивый ID, `rowId/columnId`, типизированное значение **или** формула/поле, rich-text-представление, переопределения, защита. Пустое значение, ноль и ошибка различаются.
- Ссылки на данные используют устойчивые ID. A1 — адрес интерфейса; вставка/удаление/сортировка требуют определённых правил перепривязки, а не замены подстрок.
- `TablePlacement`: лист, якорь, XY/поворот, масштаб, отображаемые строки и продолжения. Одна таблица может иметь несколько связанных представлений.
- `SourceAdapter`: тип источника, ID объектов/книги/листа/диапазона, mapping, версия/время обновления, кэш и override-политика. Импорт снимка не создаёт источник автоматически.
- Старые `rows` мигрируют в grid без потери абзацев, runs, полей и Unicode; неравные строки дополняются явными пустыми ячейками. Обратная запись в старую схему без отчёта о потерях не допускается.
- Renderer, измерение, hit testing и экспорт используют одну компоновку. Циклы формул и неизвестные поля диагностируются до autosave. Полный Excel calculation engine не подразумевается.

## Предлагаемый интерфейс

Контекстная панель таблицы: «Содержание», «Строки/столбцы», «Оформление», «Данные», «Размещение». Клик по ячейке выбирает её, двойной клик открывает вложенный текстовый редактор. Граница/отдельная ручка выбирает объект таблицы. Активная ячейка, диапазон и целый объект имеют разные визуальные состояния.

Справа — свойства текущего диапазона: адреса, тип/формула/значение, размеры, padding, выравнивание, роли, границы. Смешанные значения явно помечаются; открытие панели само по себе ничего не меняет. Формулы и связанные данные имеют индикаторы происхождения и переопределения.

Требования общего дизайна сохраняются: прямые углы, технические SVG-иконки у параметров, единицы, светлая/тёмная тема, keyboard/focus, inline validation, OK/Cancel и один undo-шаг на подтверждённое действие. Браузерные разрешения буфера/файлов обрабатываются как ограничения среды; скрытого чтения/записи нет.

## Порядок реализации

| Этап | Содержание | Условие готовности |
| --- | --- | --- |
| A1 — данные | Версионированная сетка, stable IDs, миграция rows, валидация, история | Старые документы открываются без потерь; ошибки не попадают в autosave |
| A2 — редактор | Ячейки/диапазоны, клавиатура, rich text, строки/столбцы, merge/split | Весь цикл редактирования работает с undo/cancel и тестами выделения |
| A3 — оформление | Стили, границы, padding, размеры, измерение и hit testing | Лист и экспорт совпадают по компоновке; переполнение адресуется по ячейкам |
| B1 — данные | Типы, units, безопасные формулы, search/replace, сортировка/фильтры | Детерминированный пересчёт; удаление/сортировка не ломают ссылки молча |
| B2 — документация | Шаблоны, CSV, обновления с diff, продолжения, печать | Quoted CSV и многостраничные таблицы проходят round-trip/print regressions |
| C — адаптеры | XLSX/DWG TABLE, BOM, revision, hole, bend, cut list | Каждый адаптер включается только при наличии настоящего источника и проверенной семантики |

Существующий точный CAD kernel для A/B не нужен. Автоматические таблицы отверстий/сгибов нельзя включать под видом вычисляемых до появления геометрических данных. Для generic CSV/TSV не нужен внешний офисный процессор.

## Критерии приёмки и тесты

1. Двойной клик конкретной ячейки меняет именно её; Cancel оставляет документ и dirty-состояние прежними.
2. Навигация Tab/Shift+Tab/Enter/стрелками, диапазоны и весь объект не конфликтуют; скринридер получает строку, столбец, роль и состояние.
3. Вставка/удаление строк и столбцов сохраняет ID незатронутых ячеек, форматы и связи; ошибочные ссылки показаны явно.
4. Merge нескольких непустых ячеек показывает правило объединения. Split не обещает восстановление уже удалённых значений. Undo возвращает исходные данные полностью.
5. Форматирование диапазона не заменяет значения/формулы. Сброс переопределений возвращает стиль без потери полей.
6. `0012`, `0`, пустой текст, null, дата и число с локальной запятой не смешиваются. Расчёты с несовместимыми единицами дают диагностируемую ошибку.
7. Копирование формулы проверяет относительные/абсолютные ссылки; цикл, деление на ноль и удаление цели не превращаются в ноль или неотмеченный старый кэш.
8. Сортировка переставляет целые логические записи; фильтр не удаляет строки; merges и формулы имеют явную политику.
9. Импорт CSV проверяется на кавычках, экранировании, quoted newline, BOM/UTF-8, пустых крайних полях и разделителях `,`, `;`, TAB.
10. Связанный источник обновляется через diff; ручные overrides не теряются молча. Отсутствие источника и отмена асинхронного действия не перезаписывают другую вкладку или новые правки.
11. Экспорт CSV явно различает значение и формулу; опасный spreadsheet-префикс не исполняется автоматически при открытии файла получателем.
12. Cell overflow проверяется после padding/merge/rotation. Повторяемая шапка и продолжение совпадают на листе и PDF; скрытые/непечатные области не протекают в экспорт.
13. Native JSON reopen сохраняет grid/IDs/формулы/runs/поля. DXF LINE/TEXT предупреждает о потере табличной семантики; TABLE round-trip — отдельный тест отдельного адаптера.
14. Generic table, BOM, revision, hole, bend и stamp не взаимозаменяются при копировании, текстовом merge или смене источника.
15. Лимит проверяется по суммарным ячейкам и объёму текста до allocation; большие импорты/пересчёты можно отменить. Макросы, eval и произвольный код из файла не исполняются.

Каждый этап реализации требует module-тестов, TypeScript/build и реальных браузерных сценариев на том же коммите. Этот PR содержит только спецификацию; функциональные критерии выше пока не считаются выполненными.
